# Product Leadership Plan

Month 6 converts engineering proof into product and leadership proof.

## Artifacts

| Artifact | Purpose | Template |
|----------|---------|----------|
| PRD | define problem, users, scope, metrics, risks | [../templates/product-requirements-template.md](../templates/product-requirements-template.md) |
| User interview notes | validate problem and workflow | weekly review or tracking note |
| MVP spec | choose smallest useful AI workflow | design doc |
| Pitch outline | communicate why it matters | portfolio note |
| Stakeholder memo | explain tradeoffs to non-technical readers | Google Technical Writing style |
| Final architecture review | prove senior communication | architecture review doc |
| AI product case study | package problem, build, evals, incidents, tradeoffs | portfolio case study |

## Leadership Bar

- State the user problem before the model choice.
- Show the non-AI baseline.
- Define success and failure metrics.
- Explain cost and latency constraints.
- Name security and reliability risks.
- Make tradeoffs understandable to non-engineers.
