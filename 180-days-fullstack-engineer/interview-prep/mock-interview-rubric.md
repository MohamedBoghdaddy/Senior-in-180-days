# Mock Interview Rubric

Use this rubric for DSA mocks, system design drills, code review drills, and final interview rehearsals.

## Score Scale

| Score | Meaning |
|------:|---------|
| 1 | Could not make progress without major hints. |
| 2 | Understood part of the problem but missed the core pattern or constraints. |
| 3 | Reached a working solution with gaps in explanation, edge cases, or complexity. |
| 4 | Solved correctly with clear reasoning and minor polish issues. |
| 5 | Interview-ready: clear, correct, tested, tradeoff-aware, and calm. |

## DSA Rubric

| Category | 1 | 3 | 5 |
|----------|---|---|---|
| Problem understanding | Misses constraints | Restates most requirements | Restates requirements and asks useful clarifying questions |
| Pattern selection | Guesses randomly | Finds pattern after exploration | Identifies pattern and explains why it fits |
| Correctness | Fails key cases | Works on common cases | Handles edge cases and proves invariant |
| Complexity | Unknown or wrong | Gives basic Big-O | Gives accurate time and space with tradeoffs |
| Communication | Mostly silent | Explains after coding | Thinks aloud clearly throughout |
| Debugging | Stuck after bug | Fixes with hints | Tests deliberately and fixes independently |

## System Design Rubric

| Category | 1 | 3 | 5 |
|----------|---|---|---|
| Requirements | Vague | Captures basics | Separates functional and nonfunctional requirements |
| Architecture | Random components | Plausible service sketch | Clear boundaries, data flow, and ownership |
| Data model | Missing | Basic entities | Tenant-safe model with indexes and tradeoffs |
| Scale and reliability | Hand-wavy | Mentions caching or queues | Gives capacity assumptions, bottlenecks, SLOs, and failure modes |
| Tradeoffs | None | Some pros and cons | Chooses deliberately and explains alternatives |

## Code Review Rubric

| Category | 1 | 3 | 5 |
|----------|---|---|---|
| Bug discovery | Finds superficial issues | Finds one real risk | Finds behavior, security, testing, and maintainability risks |
| Evidence | No references | Some code references | Precise references and reproducible reasoning |
| Fix quality | Vague | Plausible | Small, testable, production-aware fix |
| Tone | Harsh or unclear | Understandable | Clear, respectful, senior-level review language |
